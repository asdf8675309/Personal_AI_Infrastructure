# Proposal: Fix RebuildArchSummary path mismatch causing redundant regeneration on every Stop

**Status:** Ready for PR — verified against the v5.0.0 release bundle 2026-06-10
**Co-authored-by:** Claude (Anthropic)
**Target:** `.claude/hooks/handlers/RebuildArchSummary.ts` (line 27), plus stale doc-comments in `.claude/PAI/TOOLS/ArchitectureSummaryGenerator.ts`
**Patches:** `Proposals/patches/0001-rebuild-arch-summary-path.patch`, `Proposals/patches/0002-arch-summary-generator-doc-comments.patch`
**Severity:** Low impact per run (15ms wasted/Stop) but unbounded over time and contributes to post-response latency that compounds with other Stop hooks.

## Problem

`DocIntegrity.hook.ts` fires on every Stop event and calls `handleRebuildArchSummary()`. That handler decides whether the architecture summary needs to be regenerated by stat'ing its output path and comparing mtimes against tracked source files. The output path constant disagrees with where the generator actually writes:

- `RebuildArchSummary.ts:27` expects:
  ```ts
  const output = join(paiDir, "DOCUMENTATION", "PAI_ARCHITECTURE_SUMMARY.md");
  ```
- `ArchitectureSummaryGenerator.ts:25` writes:
  ```ts
  const SUMMARY_OUTPUT = path.join(PAI_DIR, "DOCUMENTATION", "ARCHITECTURE_SUMMARY.md");
  ```

Because the `PAI_`-prefixed file never exists on disk, `existsSync(output)` always returns `false`, so the handler hits the "missing — regenerating" branch every single Stop:

```ts
const outputStat = existsSync(output) ? statSync(output) : null;
if (!outputStat) {
  console.error("[RebuildArchSummary] Architecture summary missing - regenerating");
  await rebuild(generator, paiDir);
  return;
}
```

`rebuild()` spawns a fresh `bun` subprocess (`bun ArchitectureSummaryGenerator.ts generate`) that reads `PAISystemArchitecture.md`, regenerates the summary, and writes it back to the canonical (non-prefixed) name. The mtime-comparison branch — the one that should keep the handler a fast no-op — is never reached.

Evidence:

1. **Live filesystem state:** `ls ~/.claude/PAI/DOCUMENTATION/ARCHITECTURE_SUMMARY.md` exists. `ls ~/.claude/PAI/DOCUMENTATION/PAI_ARCHITECTURE_SUMMARY.md` does not (`stat: No such file or directory`).
2. **Stop hook transcripts** going back to 2026-05-03 contain the line:
   ```
   [RebuildArchSummary] Architecture summary missing - regenerating
   [RebuildArchSummary] Regenerated DOCUMENTATION/ARCHITECTURE_SUMMARY.md
   ```
   on every Stop, regardless of whether any source file changed.
3. **Cross-reference confirms** which name is canonical:
   - `PAI_SYSTEM_PROMPT.md` → `PAI/DOCUMENTATION/ARCHITECTURE_SUMMARY.md`
   - `PAISystemPhilosophy.md` → `[ARCHITECTURE_SUMMARY.md](./ARCHITECTURE_SUMMARY.md)`
   - `CONTEXT_ROUTING.md` → `~/.claude/PAI/DOCUMENTATION/ARCHITECTURE_SUMMARY.md`
   - `IsaSystem.md` → `PAI/DOCUMENTATION/ARCHITECTURE_SUMMARY.md`

   Every caller uses the non-prefixed name. The generator's output matches. Only the handler's path constant — and a couple of stale `*` doc-comments in the generator and `settings.json` — carry the typo functionally. The prefixed name also appears in several documentation files (HookSystem.md, PAISystemArchitecture.md, Tools.md, and two others); those are cosmetic and left for a separate docs sweep.

## Why this matters

Individually small (the generator runs in ~15ms in the steady state), but:

- It's wasted CPU and a `bun` subprocess fork on every single response forever.
- The `[RebuildArchSummary] Architecture summary missing` log line is misleading — the file is never missing.
- Combined with `DocIntegrity.hook.ts` not being registered as `async: true` (separate proposal: `DocIntegrityStopHookAsync.md`), this contributes to a longer-than-necessary post-response window, which interacts poorly with the Claude Code `/remote-control` bridge during heavy forked-execution skills (`/Knowledge ingest`, deep ingests, long-running `context: fork` skills).
- It defeats the mtime-staleness check that the rest of the handler implements — that check is meant to make the hook a fast no-op when nothing changed, but it never runs.

## Proposed fix

Two-line change. Match the handler's expected path to the generator's actual output. Clean up the stale `PAI_`-prefixed references in the generator's header comment and CLI help string for consistency.

```ts
// hooks/handlers/RebuildArchSummary.ts
- const output = join(paiDir, "DOCUMENTATION", "PAI_ARCHITECTURE_SUMMARY.md");
+ const output = join(paiDir, "DOCUMENTATION", "ARCHITECTURE_SUMMARY.md");
```

```ts
// PAI/TOOLS/ArchitectureSummaryGenerator.ts (doc comments only)
- * ArchitectureSummaryGenerator — Generate PAI_ARCHITECTURE_SUMMARY.md from source docs
+ * ArchitectureSummaryGenerator — Generate ARCHITECTURE_SUMMARY.md from source docs
…
-   generate    Generate/regenerate PAI_ARCHITECTURE_SUMMARY.md
+   generate    Generate/regenerate ARCHITECTURE_SUMMARY.md
```

Before the patch the same probe always printed `Architecture summary missing - regenerating` and advanced the mtime.
