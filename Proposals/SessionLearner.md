# Proposal: LLM-Based Session Learner — Replace Regex Mining

**Status:** Ready for PR — implemented and running locally since 2026-05-16; revised for base-v5.0.0 applicability 2026-06-11
**Co-authored-by:** Claude (Anthropic)
**Target:** `PAI/TOOLS/SessionLearner.ts` (new), plus a one-line swap wherever the install schedules `SessionHarvester.ts --mine` (base v5.0.0 ships no harvest pipeline script — scheduling is cron/launchd/user-script territory)
**Owner:** @asdf8675309
**Branch (when ready):** `proposal/session-learner`

## Problem

`SessionHarvester.ts --mine` uses regex patterns to extract decisions, preferences, milestones, and problems from session JSONL transcripts. In practice, the patterns fire inside the assistant's own response-template artifacts (mode banners, status lines, code-fence markers), producing high-volume false positives. Each candidate's title is generated by truncating the first 60 chars of matched content, which leaks template formatting into the title. After `toKebabCase` and the harvester's `targetPath`-exists dedup, hundreds of distinct moments collapse onto identical slugs. The system has accumulated **253 junk seedlings** in `KNOWLEDGE/Ideas/` matching `^(decision|milestone|problem|preference)-.*\.md` patterns; every subsequent mining run now correctly dedups to zero against this junk wall.

User-initiated `/Knowledge ingest <url>` works well (193 real notes in 14 days). Autonomous session-to-knowledge ingestion does not.

## Diagnosis

The regex-mining approach is fragile:

1. Generic verbs ("decided", "problem", "broken") match in any context — including the assistant's mode-detection banners and status output.
2. First-60-char title generation cannot distinguish a real decision ("we decided to use Cloudflare Workers because…") from a banner artifact ("════ PAI | NATIVE MODE ═══════════════════════").
3. Slug-exact dedup amplifies the problem: once one junk slug occupies a filename, every near-duplicate downstream is filtered against it.

Cheap pattern matching at the source cannot recover from these failures. The unit of intelligence required is summarization + classification, which is what an LLM does naturally.

## Proposal

Add `PAI/TOOLS/SessionLearner.ts`. Swap it in wherever the install schedules `SessionHarvester.ts --mine`. Archive existing junk seedlings.

### Pipeline shape

```
SessionLearner.ts run
  → list session JSONLs (last 2 days, configurable)
  → for each session:
      → strip Bob's template artifacts (NATIVE MODE banners, status lines, code fences)
      → cap at ~12K chars (token economy)
      → Inference.ts call with strict-JSON extraction prompt
      → validate JSON shape
      → for each insight {title, domain, type, tags, content, quality}:
          → quality < threshold → skip + log
          → Jaccard(title_tokens, every existing KNOWLEDGE/<domain>/* title) > 0.7 → skip + log
          → write to KNOWLEDGE/<domain>/<slug>.md
      → record one session-learner-ledger entry per session (candidates_generated, written, skipped)
      → (optional) record a billing-ledger entry per session — only if the separate
        per-call billing-ledger proposal is adopted; base v5.0.0 has no BillingLedger,
        so the import and call are guarded behind its presence
```

### Extraction prompt (LLM)

```
You are extracting durable knowledge from a Claude Code session transcript.

Return 0 to 3 genuinely-interesting insights from the conversation below. Each
insight must be:
- A non-obvious fact, decision, learning, or pattern
- Something that would NOT be derivable by re-reading the code or git history later
- Specific to this session — generic AI / coding wisdom is NOT an insight

For each insight, return strict JSON:
{
  "insights": [
    {
      "title": "Specific, descriptive title — never starts with 'decision:' or session metadata",
      "domain": "People" | "Companies" | "Ideas" | "Research",
      "type": "idea" | "person" | "company" | "research",
      "tags": ["tag1", "tag2", ...],
      "content": "1-3 paragraph summary of the insight, plus a context line",
      "quality": 1-10 integer
    }
  ]
}

If nothing meets the bar, return {"insights": []}.

--- SESSION ---
{cleaned_transcript}
```

### Feature flag

`PAI_SESSION_LEARNER` env var. Default on. Set to `0` to disable; the runner logs `{disabled: true}` and exits without LLM calls.

### Config file

`MEMORY/STATE/session-learner-config.json` (auto-created with defaults):

```json
{
  "enabled": true,
  "model": "haiku",
  "max_inferences_per_run": 5,
  "days_lookback": 2,
  "min_quality_threshold": 6,
  "max_chars_per_session": 12000,
  "dedup_jaccard_threshold": 0.7
}
```

### Scheduling change (example)

Base v5.0.0 doesn't ship a harvest pipeline script — `SessionHarvester.ts --mine` runs however the user scheduled it (cron, launchd, or a wrapper script). The swap is one line wherever that lives. Example wrapper:

```diff
 #!/bin/bash
 set -e

 BUN="$(command -v bun)"
 TOOLS="$HOME/.claude/PAI/TOOLS"

-$BUN run $TOOLS/SessionHarvester.ts --mine --days 2
-$BUN run $TOOLS/KnowledgeHarvester.ts harvest --source queue
+$BUN run $TOOLS/SessionLearner.ts run
+$BUN run $TOOLS/KnowledgeHarvester.ts harvest --source queue
```

`SessionHarvester.ts` itself is **not** modified — still callable directly. Just unscheduled.

### Junk seedling archive

One-shot bash to move 253 files matching `^(decision|milestone|problem|preference)-.*\.md` AND containing `mined` in their frontmatter tags into `KNOWLEDGE/Ideas/_archive/junk-mined-pre-2026-05-16/`. Master MOC regenerated. Reversible — files are moved, not deleted.

## Why upstream-able

Any PAI user running stock `SessionHarvester.ts --mine` silently accumulates the same junk. The fix:
1. Costs ~$1/month per user (Haiku rate).
2. Reuses an existing PAI primitive (`Inference.ts`) and respects the central inference-routing pattern.
3. Single-flag reversible.
4. Restores `KNOWLEDGE/` to containing only real knowledge.
